Gate list for web-surface, has-cta: 18 question(s).

Look questions, for the critics, pass 4 of 4, treatment and value, once the function and role passes' fixes land: treatment: interaction, layout, surfaces, system, text, typography; value: typography:

40. vault.focus-colour: Is the site's focus colour kept off hover and brand accents, either the browser's own two-colour ring or a project colour paired with a second colour so the ring clears 3:1 on every ground it meets?
   Applies to: every focus indicator, and every other use of the focus colour
41. vault.alignment-lines-look: Where the main content is laid on columns with no CSS grid, does each top-level content container start and end on a shared column line, never in a gutter or margin?
   Applies to: every top-level content container (text block, card, image, table, form) in the main content area that no CSS grid places
42. vault.alignment-break: Does each part or section that leaves the page's shared alignment lines show why it does: it leads the page, sets one block apart, or is an image band?
   Applies to: a full-bleed part or centred section among sections that share the page's alignment lines
43. vault.optical-icon: Does each icon beside text look aligned with it, its drawn shape centred on the text's line and balanced in its box, the padding on a button's icon side trimmed, rather than aligned by its box alone?
   Applies to: an icon beside text: in a button, a link, a list item or a label
47. vault.grid-ornament: Is a visible page frame, grid line or crosshair mark the site's own signature, drawn in vault.border-roles' decorative edge and held at one position on every page, rather than a default ornament or the broadsheet-hairline look, and kept off working areas?
   Applies to: every visible page frame, column rule, grid line or crosshair mark
55. vault.inverse-surface-look: Is the action in each snackbar or toast set in the inverse primary, the theme's primary as it reads on the inverse surface?
   Applies to: every snackbar and toast that holds an action
56. vault.shadow-meaning: Is each edge outside the controls that carries meaning drawn as a `border` or `outline`, or as a `box-shadow` over a transparent `border` or `outline` of equal width, so no meaning rests on a shadow that forced-colours mode drops?
   Applies to: every edge or level outside the controls that carries meaning: a selected or current state, the edge of a menu, dialog, popover or card that must stand apart from what lies under it
57. vault.surface-layers: Does every container fill come from a small set of named surface levels (page ground, container, nested container, and a sunken well where one is used), a container nested in another taking the next level rather than its parent's tone, a sunken well used only on the default level as a backdrop that groups content such as a board's columns and never inside a raised or overlay surface, and any border on a level taking the border paired with that level?
   Applies to: every container fill: page ground, card, panel, well
58. vault.card-type: Does a card take a treatment unlike the rest of its set only where it is a different kind of thing?
   Applies to: every set of like cards: one list, grid or carousel
59. vault.glass-dimming: Where a clear glass layer floats over bright media, does a dark dimming layer of about 35% opacity sit behind it, and is none added over media already dark or with its own dimming?
   Applies to: every clear, highly translucent glass layer over photos, video or other bright media
61. vault.card-image-tint: Where repeated cards each take a tint from their own image, is the tint a low-chroma container tone drawn from the image's source colour with the card's text measured on it, used only where the image is the item's identity (an album, a place, a video), and never where a tint could read as a status or a category?
   Applies to: every set of repeated cards that each carry an image
63. vault.generated-content-look: Is every `::before` and `::after` symbol a screen reader announces one that carries meaning, a decorative one kept out by an empty alternative (`content: "→" / ""`) or `aria-hidden` on its element?
   Applies to: every `::before` and `::after` whose `content` holds text or a symbol
64. vault.lang-parts-look: Does each passage or phrase in a language other than the page's carry its own `lang`?
   Applies to: every passage or phrase in a language other than the page's, save proper names, technical terms and words the surrounding language has taken in
65. vault.kept-breaks: Does text whose line breaks carry meaning, and only that text, keep its typed breaks and repeated spaces, by `pre`, `white-space-collapse: preserve` or `preserve-breaks`?
   Applies to: code, poetry, addresses and other text whose line breaks carry meaning
67. vault.text-case: Is each of these in sentence case, capitals kept for the first word, proper nouns and acronyms, one case for each kind of element across the site, with no title case and no capitals beyond the short labels `vault.caps-extent` allows, unless the project's rules file names another case?
   Applies to: every heading, page title, button label, link, tag or status label, list item, menu item and tooltip
68. vault.type-width: Is a narrow width kept to labels and dense cells, no condensed width in text read at a glance, and a wide width only in short headings and pull quotes with room for it?
   Applies to: every face with a width axis or width cuts
69. vault.text-spacing-reveal: Once WCAG 1.4.12's four spacing values are set, can the visitor show the whole of each such text, by the control beside it or on the page its link opens?
   Applies to: each text `check-layout.py --text spacing` lists as hidden in a link or beside a control
70. vault.text-style-count: Is every text style on the page (its face, size, weight and colour together) one of the site's named type-scale styles, with no one-off combination outside the scale and the lead or display sizes held to at most two elements a view?
   Applies to: all visible text on the page
